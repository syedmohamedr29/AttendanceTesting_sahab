## 3. Module 1: Holiday Calendar Module (`ERP.Attendance.HolidayCalendars`)

> **Target Collection:** `Sahab.ERP.Attendance.HolidayCalendars` | **Service:** `SP.AttendanceSvc` (.NET 9)
> **Base Route:** `/api/companies/{companyId}/holidaylist` | **Controller:** `HolidayCalendarController`

### <a id="defect-20261103-01"></a>🔴 DEFECT-20261103-01: Audit Field `CreatedBy` Persists as Plain Email String Instead of Composite User Identity
- **Severity:** 🟡 P2 (Major / Audit Trail)
- **Affected Route:** `POST /api/companies/{companyId}/holidaylist`
- **Database Target:** `Sahab.ERP.Attendance.HolidayCalendars.CreatedBy`
- **Status:** ❌ **Open / Verified on Swagger & MongoDB Compass**

#### 1. Problem Summary
When a holiday calendar is created, the system stores `CreatedBy` as a raw string `"syed.mohamed@comm-it.in"` instead of a structured composite identity object (`{ "userId": "...", "loginId": "...", "name": "..." }`). This violates Sahab enterprise audit guidelines.

#### 2. Steps to Reproduce
1. Authenticate via Swagger or UI as an admin user.
1. Execute `POST /api/companies/{companyId}/holidaylist` to create a holiday calendar.
1. Inspect the created document in MongoDB Compass.

#### 3. Expected vs Actual Result
- **Expected:** `CreatedBy` must persist as a composite object `{ userId, loginId, name, email }` populated from JWT claims.
- **Actual:** `CreatedBy` persists as a simple string `"syed.mohamed@comm-it.in"`.

#### 4. Photographic Proof
[🔍 View Evidence 18](file:///d:/Code/Attendance%20Testing/defect_evidence/evidence_18_holiday_calendar_createdby_email_tenantname_empty.jpg)

![DEFECT-20261103-01](defect_evidence/evidence_18_holiday_calendar_createdby_email_tenantname_empty.jpg)

#### 5. Developer Remediation (.NET 9 C#)
```csharp
// Remediation for DEFECT-20261103-01
In `CreateHolidayCalendarCommandHandler.cs`, inject `ICurrentUser` and map `calendar.CreatedBy = new AuditUser { UserId = _currentUser.Id, Email = _currentUser.Email, Name = _currentUser.Name };`.
```

### <a id="defect-20261103-02"></a>🔴 DEFECT-20261103-02: `TenantName` Persists as `Object (empty)` `{}` in MongoDB During Creation & Updates
- **Severity:** 🟠 P1 (Critical / Data Integrity)
- **Affected Route:** `POST /api/companies/{companyId}/holidaylist` & `PATCH /{id}/{year}`
- **Database Target:** `Sahab.ERP.Attendance.HolidayCalendars.TenantName`
- **Status:** ❌ **Open / Verified on Swagger & MongoDB Compass**

#### 1. Problem Summary
Holiday calendar documents created in MongoDB Compass store `TenantName: Object (empty)` `{}`. The backend handler fails to resolve or populate the tenant name from `ICurrentTenant` or JWT claims.

#### 2. Steps to Reproduce
1. Execute `POST /api/companies/{companyId}/holidaylist` with valid calendar payload.
1. Open MongoDB Compass and view the persisted document.

#### 3. Expected vs Actual Result
- **Expected:** `TenantName` must be populated with multilingual values `{ en: "Attendance", ar: "الحضور" }`.
- **Actual:** `TenantName` is stored as an empty BSON object `{}`.

#### 4. Photographic Proof
[🔍 View Evidence 19](file:///d:/Code/Attendance%20Testing/defect_evidence/evidence_19_holiday_calendar_tenantname_empty_red_circle.jpg)

![DEFECT-20261103-02](defect_evidence/evidence_19_holiday_calendar_tenantname_empty_red_circle.jpg)

#### 5. Developer Remediation (.NET 9 C#)
```csharp
// Remediation for DEFECT-20261103-02
In `CreateHolidayCalendarCommandHandler.cs`, inject `ICurrentTenant` and assign `calendar.TenantName = new MultilingualString { En = _currentTenant.Name, Ar = _currentTenant.ArabicName };`.
```

### <a id="defect-20261103-03"></a>🔴 DEFECT-20261103-03: `isActive: false` in Request Payload Ignored by Backend Handler and Persisted as `IsActive: true`
- **Severity:** 🟠 P1 (Critical / API Contract)
- **Affected Route:** `POST /api/companies/{companyId}/holidaylist`
- **Database Target:** `Sahab.ERP.Attendance.HolidayCalendars.IsActive`
- **Status:** ❌ **Open / Verified on Swagger & MongoDB Compass**

#### 1. Problem Summary
When creating a calendar with `"isActive": false`, the server accepts the payload with HTTP 200 OK but forcibly overrides `IsActive = true` in MongoDB. Clients cannot create a draft inactive calendar.

#### 2. Steps to Reproduce
1. Send `POST /api/companies/{companyId}/holidaylist` with `"isActive": false`.
1. Inspect the created document in MongoDB Compass.

#### 3. Expected vs Actual Result
- **Expected:** MongoDB document must preserve client's `IsActive: false` setting.
- **Actual:** MongoDB document has `IsActive: true` (hardcoded by backend handler).

#### 4. Photographic Proof
[🔍 View Evidence 20](file:///d:/Code/Attendance%20Testing/defect_evidence/evidence_20_holiday_calendar_isactive_false_ignored_stored_true.jpg)

![DEFECT-20261103-03](defect_evidence/evidence_20_holiday_calendar_isactive_false_ignored_stored_true.jpg)

#### 5. Developer Remediation (.NET 9 C#)
```csharp
// Remediation for DEFECT-20261103-03

```

### <a id="defect-20261103-04"></a>🔴 DEFECT-20261103-04: Non-Existing Holiday Type ID (`holidayTypeId`) Accepted Without Master Catalog Validation
- **Severity:** 🟠 P1 (Critical / Referential Integrity)
- **Affected Route:** `POST /api/companies/{companyId}/holidaylist`
- **Database Target:** `Sahab.ERP.Attendance.HolidayCalendars.YearlyCalendar.HolidayLists[].HolidayType`
- **Status:** ❌ **Open / Verified on Swagger & MongoDB Compass**

#### 1. Problem Summary
Client submits arbitrary fake UUIDs for `holidayTypeId` (e.g. `"11111111-2222-3333-4444-555555555555"`). The server accepts with HTTP 200 OK and stores non-existing holiday types in MongoDB without checking catalog.

#### 2. Steps to Reproduce
1. Send `POST /holidaylist` with random non-existing UUID for `holidayTypeId`.
1. Verify server response and inspect MongoDB Compass.

#### 3. Expected vs Actual Result
- **Expected:** HTTP 400 Bad Request (`Cit.Attendance:1708`: 'Holiday type ID does not exist in the master catalog.').
- **Actual:** HTTP 200 OK. Fake holiday type saved into MongoDB.

#### 4. Photographic Proof
[🔍 View Evidence 21 & 22](file:///d:/Code/Attendance%20Testing/defect_evidence/evidence_22_holiday_calendar_invalid_holidaytypeid_compass.jpg)

![DEFECT-20261103-04](defect_evidence/evidence_22_holiday_calendar_invalid_holidaytypeid_compass.jpg)

#### 5. Developer Remediation (.NET 9 C#)
```csharp
// Remediation for DEFECT-20261103-04
In `CreateHolidayCalendarCommandValidator.cs`, add `RuleForEach(x => x.YearlyCalendar.HolidayLists).MustAsync(async (item, ct) => await _holidayTypeRepo.ExistsAsync(item.HolidayTypeId, ct));`.
```
